XNG 公共來源規則與靈動島接入（2026-10-03）

每位使用者自行架設 XNG，Cloudflare 只配送公開核心與優化參數。
沒有開放 Kent 電腦搜尋 API 給其他人，也沒有修改既有桌寵 Tunnel、DNS 或手機配對。

核心：2026.10.03-2058，搜尋算法沿用已驗收版本。
插件工具：2，增加來源規則管理與 health.rules。
來源規則：2026.10.03-1，只含來源分類、authority、penalty；首版沿用原本6個網域規則。
規則更新索引：https://xng-plugins.kentyang1993.workers.dev/xng-rules-update.json
核心更新索引：https://xng-plugins.kentyang1993.workers.dev/xng-update.json

首次使用需自備 XNG 的 Node 24、Docker 與本機 SearXNG（8888）。工具包不是完整安裝器。
已有 XNG：關閉插件管理器，備份目前 plugins/、Manage-XNGPlugin.ps1、Start/Stop，再解壓工具2到獨立 XNG 根目錄。
不得覆蓋 config/、.runtime/、runtime/ 或使用者憑證；工具包不含這些檔案。
打開 Open-XNGPlugin.cmd，在右上選「來源規則」。
檢查更新 → 確認安裝 → SHA256／JSON格式／核心回歸／規則行為校驗 → 按重新啟動 XNG。
檢查只讀，沒有自動更新；安裝不會自動重啟使用中的服務。
來源規則安裝失敗不切換指標；「回復上一版」後重啟，首版可以回到核心內建規則。

資料界線
core/ 或 .plugins/versions/：可替換核心。
config/rules-versions/：公開規則的不可覆寫版本。
config/rules-current.json：下次启动規則指標與 SHA256。
config/domain_overrides.local.json：個人規則，公共更新不覆蓋，也不發布。
.runtime/：引擎健康狀態與運行資料；記憶體快取遵守既有TTL，重啟會自然清空。
不把快取或新日期視為永久知識或正確性保證。

個人規則範例（需要時自行新增，不會自動建立或清空）
{
  "pcgamer.com": {"authority": 0.65},
  "example.com": {"source_type": "blog", "penalty": 0.2, "blocked": false}
}
合併順序：核心內建 → 公共規則 → 個人欄位覆寫。
子網域比父網域優先。分數0～1；blocked必須布林值，硬封鎖只適用明確垃圾來源。
規則只控制最終 Evidence 排序／分類／過濾，不修改引擎開關、URL、模型、付費方案、時間預算或程式碼。
查詢規劃、原始候選與出版者身分仍由核心維護；未把所有算法改成可遠端配置。

API：8889/health 增量 rules.version/domain_count/local_domain_count/scope；schema_version仍1。
8888與8889的 /search?q=...&format=json 維持普通搜尋格式。
任何 App 接同一8889/ai/search，不需要內嵌搜尋核心。
Evidence Pack由使用端生成答案，XNG不呼叫Gemini、不消耗Gemini次數。

靈動島：Alt+A → 右鍵 → 查詢 XNG 插件版本／管理 XNG 插件／來源規則。
管理入口只開啟獨立管理器，沒有另一套更新程式。
搜尋仍是靈動島 → Gemini Hub → XNG 8889；只搜尋模式不呼叫 Gemini 模型。
停用或移除靈動島、Daily Agent 都不會停止或刪除 XNG。

校驗不是數位簽章。只從信任的公開站下載；JSON規則不執行程式碼，但錯誤權重仍可能降低品質。
每次發布需唯一版本、回歸、真實搜尋檢查；公共下載包只用明確檔案清單，禁止攜帶私人資料。
