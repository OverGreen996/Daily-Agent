# Daily Agent 維護原則

Daily Agent 與靈動島是各自獨立的程式。維護本專案時，不修改靈動島、不接回另一個程式的後端、搜尋資料或模型服務。

- Daily 使用自己的資料目錄、Ollama、搜尋金鑰、用量、輪替、快取及鎖。搜尋預設為 `DAILY_DATA/search`，選用覆寫為 `DAILY_SEARCH_DATA_DIR`；不可重新引入舊共用環境變數、另一個 App 的目錄或服務埠。
- 優先使用 Node 內建能力與現有依賴。新增依賴時，於 `ARCHITECTURE.md` 說明用途與代價，不為普通路由、設定或狀態查詢再加入大型框架。
- `core/RuntimeConfig.js` 管設定與派生路徑，`core/createAgent.js` 管組裝，`modules/Bindings.js` 管可選功能與核心的引用，`core/Shutdown.js` 管停止流程。功能實作放在 `features/<id>`；不要讓核心頂層 import 選用功能的第三方套件。
- 模組缺失、停用或初始化失敗，只應影響它及明確宣告的相依模組。`create`、`attach` 不自動推理、下載模型或消耗 API 額度；`dispose` 只清理自己擁有的資源。
- 模型服務不可用時，設定與本機記憶仍可開啟。AI 對話需要 Daily 自己的模型，不能用假回覆掩飾失敗。關閉要停止新的推理，先等候工作結束再關閉資料庫；未核實模型卸載時保留警告，不宣稱已釋放 GPU。
- 測試使用隔離資料與模擬 provider/model，避免觸碰使用者的宮殿、配對、金鑰和正式搜尋額度。不得把真實憑證印到輸出或存入版本控制。
- 新功能需驗證停用、缺檔、初始化失敗、基本聊天及資源清理。修改啟動／停止／路徑時，另驗證無選用模組、缺少分詞套件、模型服務離線以及重啟後資料保留。

常用驗證：`npm test`。安裝版離線驗證：`node scripts/independent-installed-smoke.mjs <安裝根目錄>`；它使用臨時資料，不使用使用者的真實模型或 API。

完整邊界與插件接口見 `ARCHITECTURE.md`。安裝版套用修改前保存受影響檔案，套用後核對雜湊與隔離測試；不要用整個舊快照覆蓋其他視窗的新修改。
