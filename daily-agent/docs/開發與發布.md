# 原始碼開發與發布

[← 回首頁](../../README.md) · [快速開始](快速開始.md) · [維護架構](../ARCHITECTURE.md) · [現版本介紹](現版本介紹.md)

一般使用者請下載 [單檔安裝器](https://github.com/OverGreen996/Daily-Agent/releases/latest/download/DailyAgent-Setup.exe)。以下只供修改程式及建置的人使用。

## 取得原始碼

需要 Git、Windows x64、Node 24 以上。在一般 PowerShell 執行：

```powershell
git clone https://github.com/OverGreen996/Daily-Agent.git
cd Daily-Agent
cd daily-agent
npm ci
npm test
cd ..
powershell -NoProfile -ExecutionPolicy Bypass -File .\Open-DailyManager.ps1
```

從設定視窗準備基本模型後，再開桌寵。原始碼版使用此資料夾的 `.daily-runtime` 及 `daily-agent/data`；不要與安裝版同時啟動，以免本機連接埠衝突。開發模式也可使用 `npm start` 啟動後端，但模型及 tokenizer 必須先配置。

目前預設分支是 `codex/initial-release`；直接 clone 即會取得預設分支。提交功能時從它建立自己的分支。

`npm test` 會先核對 tokenizer，首次缺少時下載 Qwen 的 tokenizer 檔案，之後沿用已校驗的副本；不下載模型權重。首次測試需要網路與少量額外磁碟空間。

## 找到對應區塊

### XNG 接入與通用工具分工

Daily Agent 維護搜尋服務的使用端。通用安裝器、管理器與公開配送工具已移到 [XNG-Plugin 獨立倉庫](https://github.com/OverGreen996/XNG-Plugin)，新工具修改與發布依該倉庫的[維護指南](https://github.com/OverGreen996/XNG-Plugin/blob/main/docs/MAINTENANCE.md)進行。

`integrations/xng-plugin/` 與 `scripts/build-xng-*.ps1` 保留作歷史配送／相容來源，不作第二套並行維護。不要為 Daily Agent、桌寵或其他 App 分別修改搜尋演算法。

搜尋算法由獨立 XNG 共用核心維護；Daily Agent 的可攜 `xng-core/` 副本只由下方同步流程更新，核對 manifest、跑完整回歸再製作新的 Daily Agent 發行版。

Git 推送、CF 配送部署、使用者安裝與本機服務啟用各自獨立。Cloudflare 只配送公開資產，不能當成遠端搜尋 API；Daily Agent 文件更新不需要部署 CF 或修改既有 Tunnel／DNS。

| 路徑 | 維護內容 |
| --- | --- |
| 根目錄 PowerShell | 安裝配置、下載、啟停與設定視窗 |
| `daily-agent/core/` | 對話編排、共用狀態及模型調度 |
| `daily-agent/modules/` | 模組宿主、目錄與設定 |
| `daily-agent/features/` | 各功能入口、指令、API、生命週期 |
| `daily-agent/plugins/` | 可參考的本機插件範例 |
| `daily-agent/desktop/` | 原生 Windows 桌寵、語音、外觀編輯器 |
| `daily-agent/android/` | 原生手機程式、測試及建置 |
| `daily-agent/ui/` | 記憶宮殿等網頁介面 |
| `daily-agent/deploy/` | 安裝器、更新、卸載、中文教學與 APK 公開資訊 |
| `daily-agent/xng-core/` | 固定的公開 XNG 核心副本及 SHA-256 清單 |
| `daily-agent/tests/` | 自動測試；實測輸出不提交 |

新增或移除功能先讀 [維護架構與插件接口](../ARCHITECTURE.md)。搜尋規則由獨立 XNG 維護，Daily Agent 只維護消費接口和相容處理。

## 測試

```powershell
cd .\daily-agent
npm test
cd ..
powershell -NoProfile -ExecutionPolicy Bypass -File .\Open-DailyManager.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -File .\daily-agent\desktop\Build-Pet.ps1 -SelfTest
```

原生建置需要 .NET Framework 編譯器及 Windows SDK／WinRT metadata。部分 Node 測試會呼叫 PowerShell／Windows 原生編譯器，不能把其他作業系統的結果當成 Windows 全套驗收。

真實模型、安裝升級、手機、Google 與外部服務的整合驗收另外記錄在 [VALIDATION.md](../VALIDATION.md)，`npm test` 不代表這些外部測試都完成。

## 更新 XNG 公開核心副本

先完成上游 XNG 測試，再同步公開檔案：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\daily-agent\scripts\sync-xng-core.ps1 -Source "C:\你的XNG資料夾\core"
cd .\daily-agent
npm test
cd ..
```

同步只讀取上游公開核心檔案，不接管它的容器、設定或資料。`snapshot.json` 固定每個檔案的 SHA-256，打包會拒絕未同步的變動；核對測試後將副本和 manifest 一起提交。

## 建置 Windows 發布包

先以原始碼配置 tokenizer，確認 `npm ci` 完成及原生桌寵可編譯。每次使用新的版本識別，避免覆蓋已建置的資料夾：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\daily-agent\scripts\build-release.ps1 -Version 0.2.2-your-build-id
```

輸出在 `daily-agent/dist/<版本>-release/`：

| 檔案 | 用途 |
| --- | --- |
| `DailyAgent-Setup.exe` | 一般使用者的單檔安裝器，內附程式 ZIP 與 SHA-256 |
| `DailyAgent-Installer.zip` | Setup 加中文教學的備用包 |
| `DailyAgent-Windows.zip`、`.sha256` | Windows OTA 使用 |
| `update.json` | Windows／Android 更新資訊 |
| `SHA256SUMS.txt` | 發布資產校驗清單 |

新 release 的 tag 必須是 `v<版本識別>`，與 `update.json` 內下載路徑一致。資產上傳並確認後，才設為最新版。不能把模型、資料庫、`.env.local`、配對資料、OAuth JSON 或私鑰放進 Git／Release。

## 建置 Android 與維護 QR Code

工具與命令見 [Android 開發教學](../android/README.md)。發行簽章金鑰由建置機私下保存，固定身份驗證與備份由 `AndroidSigning.ps1` 處理；更換金鑰會破壞覆蓋更新，不要在一般建置時使用 `-Rekey`。

APK 使用獨立 release。上傳後核對版本、大小、SHA-256 及簽章指紋，再更新：

- `deploy/android-download.json`：APK 公開 URL、版本與校驗資訊。
- `deploy/android-download.png`：指向同一 URL 的 QR Code。
- `deploy/DailyUi.cs`：原生視窗的同一下載 URL。

執行 `node --test tests/android-download.test.js tests/ota.test.js`，另用掃碼工具實際解碼 PNG 及安裝器畫面，確認它們指向同一 GitHub APK。Windows release 不需再附 APK；手機更新資訊與舊入口會轉向獨立 APK。

## 提交與維護原則

每次改動包含原因、測試與已知限制；中文說明與目前 UI 同步。歷史文件保留時間和版本，不能繼續標示為最新版。

插件只依明確宣告的模組相依，不跨模組讀寫私人資料表；自己的 timer、worker、socket 必須在 `dispose()` 清理。測試停用模組、缺失入口、驗證拒絕及停止，避免移除功能影響基本聊天。

公開的測試紀錄應省略個人記憶、裝置權杖、私人路徑與帳號資料。第三方依賴及素材保留原授權；本儲存庫未宣告統一開源授權，請勿自行推定所有內容都可任意再散布。
