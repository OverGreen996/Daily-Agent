# 桌寵動作、記憶閒聊與按需看圖 · 2026-09-27

## 動作符合實際狀態

隨機小動作只有揮手、跳躍；16 方向注視不參與自動輪替。失落只在錯誤／失敗時，思考只在實際處理或背景模型推論中，檢視只在回覆完成時播放。聊天框有焦點不再永久阻止輪替；最近 12 秒有輸入才暫停。右鍵設定新增可保存的「跟隨滑鼠視線（16 方向）」，正常動作完成後恢復追視。

實際 WinForms 計時器測試已確認焦點停在輸入框時揮手與跳躍輪替、影格前進、輸入暫停、工作狀態優先，以及 16 個方位與設定保存。報告：`test-output/native-ambient-test.json`。

## 記憶宮殿主動接話

待機會從最近七天的使用者訊息、重要 Permanent Pins，以及有原始使用者發言可追溯的 Memory Cards 選候選。每次最多讀取 32 個 Pin、24 個近期訊息、32 個 Card 摘要候選，最多每分鐘更新一次；只把一小段選中的內容交給 CPU 小模型，不載入整本 Book 或整個資料庫。

重要性、近期程度、目前程式相關性、無互動時間、無聊程度與冷卻一起決定是否發話。普通發話至少間隔 12 分鐘；記憶話題整體 45 分鐘冷卻，同一記憶至少隔 24 小時，冷卻狀態跨重啟保存。這些是最短間隔，不是固定鬧鐘。

為避免把舊事當現在的事，泡泡引用「你之前提過…」，小模型選擇接續、進展、想法或下一步的問法。保存來源 ID，自己的碎念不反過來當成使用者事實。使用者後續回應走既有 Working Memory／Pins／Book 流程；Learning = Memory，沒有 fine-tuning。

用「開啟記憶閒聊」「關閉記憶閒聊」切換。記憶檢索加接話只用 CPU 小模型；不需要 4B。

## 低頻截圖與模型輪班

使用者要求啟用後，待機時最短每 10 分鐘觀察一次目前前景視窗；切換程式也不會突破全域間隔。使用者操作閒置超過五分鐘時不截圖。截圖約 640×360，圖片在記憶體中傳遞，不保存截圖檔。既有密碼管理器／敏感標題排除仍保留，但不是全面隱私分類器。

兩種模式：

- 「開啟畫面觀察」：啟用觀察。高階模式未開時，使用本機 Windows OCR 加簡單文字分類。
- 「開啟高階畫面觀察」：也啟用畫面觀察，使用已安裝 Qwen3.5 4B 多模態，獨立 `VISION_MODEL` 角色、4K 短 context。
- 「關閉高階畫面觀察」：回到 OCR 模式；「關閉畫面觀察」：完全停止背景畫面觀察。

高階看圖流程：保存 Working Context → 取得 GPU 所有權 → 載入 4B → 看圖 → finally 卸載並以後端確認 → 恢復 Context → 通過發話判斷後才載入 CPU 0.8B → 說一句話 → 卸載 CPU 模型。短暫看圖期間會占用 VRAM；其餘 Idle 時不常駐 GPU 模型。使用者發話會取消背景工作，等卸載清理完成後讓完整 Agent 接手。

每次辨識不一定發話：活動類型有變化、可信度足夠，才建立畫面事件；再經過發話冷卻、優先級、去重。低可信度或看不懂時安靜。只累积粗略活動類型的 Habit 證據，不將原始 OCR 全文永久當知識。

## 麥克風、播放裝置與本機 TTS 聲線

右鍵桌寵 → 設定：

- 接收麥克風：Windows 預設或指定裝置。指定時以 WinMM 16 kHz/16-bit/mono PCM 串流供現有 System.Speech 辨識；錄音只留短暫、有上限的 RAM 緩衝，不寫檔。
- 語音播放裝置：Windows 預設或指定喇叭／耳機。使用 Windows SAPI 的 AudioOutput 指定本程式的播放路由，不修改 Windows 全域預設。
- TTS 聲線（Windows）：列出可供桌面 SAPI 使用的已安裝聲線，自動模式優先繁體中文。
- 測試語音播放：用目前裝置與聲線唸一句；也能說「測試語音播放」。不會因此開啟常駐聆聽或自動語音回覆。

上述選擇保存在原生桌寵設定，沿用其他既有設定。裝置 ID 與聲線 token 持久化，不保存暫時排列序號。每次打開子選單重新列舉；不存在的選擇會標記並保留，不偷偷改用其他裝置。聆聽中切換麥克風會重啟辨識，失敗嘗試回復原裝置。停止聆聽會關閉錄音串流；更換輸出、聲線或關閉語音回覆會停止舊語音。

本機已列出 AT2020USB+ 等 3 個輸入、DAWN PRO2 等 9 個輸出，以及 Hanhan／Zira／Huihui／David 4 個聲線。已驗證選定麥克風接收 PCM、聆聽切換、SAPI 播放 token、設定保存與未連接提示。真人辨識率與實際耳機聽感仍需使用者試用；合成測試音這次雖辨識出正確文字，但信心 0.265，依既有 0.55 門檻正確拒絕送出，沒有降低門檻。

Kokoro 82M v1.1 中文模型已安裝，使用 sherpa-onnx CPU provider 與四個 CPU threads，不會占用 RTX 3080 Ti VRAM。內建 103 個聲線：`zf_*` 中文女聲 55 個、`zm_*` 中文男聲 45 個、英文女聲 3 個；預設為 `zf_001`。繁體輸入只在合成管線內轉為簡體以改善發音，泡泡原文與記憶內容不變。

右鍵的「TTS 引擎／Kokoro 聲線」可以選擇，也可直接說「使用 Kokoro 語音」「使用 Windows 語音」「使用 zf_001 聲線」。只有「開啟語音回覆」後才會暖機並常駐約 520 MiB RAM；關閉語音回覆、切回 Windows TTS 或退出桌寵都會卸載。語音回覆未啟用時，單次「測試語音播放」會臨時載入，播放後卸載。此機煙霧測試暖機約 2.3 秒，暖機後產生 2.7 秒語音約 1.2 秒；實際速度會受句長與 CPU 負載影響。輸出仍經既有 SAPI audio routing 播到使用者選定的裝置。

模型來源為 [sherpa-onnx Kokoro multi-lang v1.1](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html)，Apache-2.0、本機執行且沒有逐次費用。`Setup-Kokoro.ps1` 使用固定 SHA256 驗證約 365 MB 的官方模型封裝。
